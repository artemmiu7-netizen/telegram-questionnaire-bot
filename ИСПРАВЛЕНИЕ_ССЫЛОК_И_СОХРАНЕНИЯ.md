# Исправление ссылок и сохранения анкет ММУ

Эти изменения находятся в отдельной ветке `fix/link-lead-sync`. Основная ветка `main` не изменена. Изменения пока не развёрнуты на сервере.

## Что исправлено в боте

- При сохранении контакта передаются коды УЗ и менеджера.
- При отправке анкеты бот ожидает подтверждение Google Apps Script `ok: true`.
- Если подтверждения нет, бот не сообщает абитуриенту, что анкета успешно сохранена.
- Ошибки интеграции фиксируются в логах без вывода секретов.

## Важное ограничение по Apps Script

Файл `google_apps_script_mmu.gs` в этом репозитории — старая упрощённая версия. Он не является подтверждённой копией скрипта, который сейчас развёрнут в Google Apps Script проекта ММУ.

**Не копируйте этот файл поверх действующего проекта Apps Script и не развёртывайте его как замену.** В действующем проекте есть дополнительные функции и листы для УЗ и менеджеров. Их нужно сохранить и доработать непосредственно на основе актуального кода проекта.

## Что требуется сверить в действующем Apps Script

1. Проверить обработчик `doPost(e)` и формат JSON, который отправляет бот.
2. Убедиться, что запись ищется по Telegram ID, а не только по обычному старту.
3. Сохранить `uz_code`, `manager_code` и `specialty_code` в соответствующих столбцах существующего листа `Заявки`.
4. Проверить поиск УЗ в `Реестр УЗ`, менеджера в `Менеджеры` и правила `Распределение УЗ`.
5. Только после этого включать запись в отдельные таблицы и уведомления менеджеров.

## Безопасность

Ранее секрет интеграции находился в открытом исходном коде репозитория. Его нужно заменить в настройках Deployka и Apps Script. Не вставляйте секрет в код, GitHub, сообщения или скриншоты. Удаление секрета из последнего коммита не стирает его из истории Git.

## Проверка перед публикацией

1. Сначала сверить этот код бота с актуальной конфигурацией Deployka.
2. Убедиться, что переменные `GOOGLE_SCRIPT_URL` и `GOOGLE_SHEET_SECRET` заданы в Deployka.
3. Обновить Apps Script на основе действующего проекта, не очищая и не перестраивая существующие листы.
4. Проверить обычный запуск, ссылку `?start=uz_КОД` и ссылку `?start=uz_КОД_mgr_КОДМЕНЕДЖЕРА`.
5. Проверить, что в главной таблице появились Telegram ID, источник, код УЗ и код менеджера.
6. Проверить запись на ДОД и уведомления.

Не запускайте `setupAll()` ради проверки: в старой версии скрипта эта функция очищает и заново формирует листы ДОД и Статистика.


## Индивидуальные таблицы менеджеров — новый модуль

Добавлен файл `google_apps_script_manager_routing_v1.gs`.

Он предназначен для добавления отдельным файлом в действующий расширенный Apps Script, а не для замены существующего обработчика. Модуль:

- находит менеджера по `manager_code` в листе `Менеджеры`;
- использует или создаёт его отдельную Google-таблицу;
- сохраняет ID и URL таблицы в столбцы `ID таблицы менеджера` и `Ссылка на таблицу менеджера` (если заголовков нет, добавляет их справа);
- при наличии `Google email` выдаёт менеджеру доступ редактора;
- создаёт внутри таблицы менеджера отдельный лист для каждого УЗ по коду и названию из `Реестр УЗ`;
- записывает полную строку заявки и обновляет её по Telegram ID, чтобы повторный запрос не создавал дубликат;
- не очищает и не перестраивает существующие листы.

### Подключение к действующему doPost

В действующем расширенном Apps Script добавьте файл целиком как новый файл `.gs`. Затем в существующем `doPost(e)`, после успешного upsert главной строки и после `SpreadsheetApp.flush()`, вызовите модуль, используя реальные переменные обработчика:

```javascript
const managerRoute = mmuSyncLeadToManagerBookV1_(
  mainSheet.getParent(),
  mainSheet,
  mainRow,
  body
);
```

Здесь `mainSheet` — фактический лист «Заявки», `mainRow` — номер только что записанной/обновлённой строки, `body` — нормализованный payload с `manager_code` и `uz_code`. Если в действующем doPost эти переменные называются иначе, передайте соответствующие фактические значения. Не создавайте второй doPost и не заменяйте текущую маршрутизацию УЗ.

Включите `managerRoute` в JSON-ответ `ok:true`. Если модуль выбрасывает ошибку, doPost должен вернуть `ok:false`. Главная запись при этом уже может быть сохранена; повторный запрос безопасен благодаря upsert по Telegram ID.

### Важно перед включением

- В листе `Менеджеры` должны быть корректные `Код менеджера`, `Статус` и, для автоматической выдачи доступа, `Google email`.
- Менеджеры получают доступ редактора к своей таблице. Внутри неё хранятся только заявки с соответствующим `manager_code`.
- Доступ к ранее созданной таблице не отзывается автоматически при смене менеджера или его статуса.
- Модуль ещё не подключён к развёрнутому Apps Script и не проверен на реальных таблицах. Не публикуйте его до добавления вызова в действующий doPost и проверки тестовой заявкой.
